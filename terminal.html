Type help to begin. --- {%- comment -%} Post index, rendered once at build time. Read by assets/js/terminal.js. Why embedded rather than a fetched JSON file: Jekyll already has this data at build time, so a runtime fetch would add a round-trip, an extra file, and a new failure mode (offline / 404) for no gain. It also cannot go stale, because it is regenerated on every build. ESCAPING, do not simplify this: `| jsonify` alone is NOT enough. It escapes quotes and backslashes for JSON, but it does not touch ``, and the HTML parser closes this block at the first literal `` it sees, no matter that we are inside a JSON string. A post titled `foo ` would therefore terminate the data block and inject live HTML. Verified 2026-08-16 with a probe post: it really does happen. So every value is `jsonify`'d for JSON correctness and then has `<` replaced, which makes a literal `` unrepresentable while leaving the JSON valid. terminal.js reverses nothing: it renders these strings with textContent, so `\u003c` arrives as a plain "<" character on screen. Do NOT change the script type either: `application/json` means the browser parses this as data and never executes it. {%- endcomment -%} {%- assign lt = '\u003c' -%}
